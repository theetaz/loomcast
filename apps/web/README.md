# @loomcast/web

The Loomcast web app: a React 19 single-page app built with Vite, TanStack Router (file
routes) and TanStack Query. Components, tokens and motion come from `@loomcast/ui`; request
and event shapes come from `@loomcast/contracts`.

## Scripts

```sh
pnpm --filter @loomcast/web dev        # http://localhost:5173, proxies /api to 127.0.0.1:8790
pnpm --filter @loomcast/web dev:mock   # same app against the in-browser mock API, no server needed
pnpm --filter @loomcast/web build      # dist/, served by the API in production
pnpm --filter @loomcast/web typecheck  # generates the route tree, then tsc
pnpm --filter @loomcast/web test       # vitest + Testing Library + jsdom, fetch mocked with MSW
```

`src/routeTree.gen.ts` is generated by the router plugin (dev, build, tests) and by
`tsr generate`. It is git-ignored; run `pnpm --filter @loomcast/web routes` to refresh it by hand.

### Mock mode

`dev:mock` starts [MSW](https://mswjs.io) in the browser with demo projects and a paired
studio. Sign in with `owner@loomcast.test` / `loomcast-demo-password`. Creating a project
also publishes a `project.created` event on the mock `/api/stream`. The mocks are never part
of a production build.

The mock studio agent answers chat messages: the job is dispatched, reports tool activity,
streams its reply and stores it, publishing the same live events as the real system. A
message containing `[fail]` fails, and `loomcastMock.setStudioOnline(false)` in the console
takes the studio agent offline so new messages wait (set it back to `true` to run them).

Settings → Members lists demo members. Inviting someone shows a set-password link. The mock
API lives in the page and a reload resets it, so open the link without reloading: for example
`history.pushState({}, "", link); dispatchEvent(new PopStateEvent("popstate"))` in the console.

The demo projects also have series and content items in every pipeline state
(`src/mocks/content.ts`); the demo series get formats with their own rules and history
(`src/mocks/formats.ts`, default rules for any other series), and uploads go to a pretend
object store (`src/mocks/uploads.ts`). Producing an item walks it through script, storyboard,
voice and render to review, one version every second or so, with the live events the API sends.

The calendar's mock (`src/mocks/calendar.ts`) adds planning channels, links them to the demo
series and puts posts on the next slots of each series' cadence (from the formats in
`src/mocks/formats.ts`), leaving a few slots open, with published and missed posts in the past
(`db.channels`, `db.seriesChannels`, `db.posts`). It answers `calendar.get`, the scheduled-post
routes and `channels.list`, and publishes `post.updated` like the scheduler will.

## Calling the API

```ts
import { api, ApiError, errorMessage } from "@/lib/api";

const project = await api.request("projects.get", { params: { idOrSlug } });
await api.request("projects.create", { body: { name } });
```

- Route names, path parameters, bodies, queries and responses are typed from the contracts.
  Success bodies are validated with the route's schema.
- Every request sends `credentials: "same-origin"` and JSON headers, which the CSRF guard needs.
- Failures throw `ApiError` (`status`, `code`, `message`, `details`); `status` is 0 when the
  server could not be reached. `errorMessage(error)` gives a sentence for the UI.
- A 401 from a session route sends the user to `/login?next=<current path>`. Pass
  `redirectOnUnauthorized: false` to handle it yourself, as the auth guard does.
- Wrap calls in `queryOptions` next to the feature (`features/*/queries.ts`) and take keys from
  `queryKeys`.

## Live events

The `_app` layout keeps one `EventSource` on `/api/stream` open through `useLiveEvents()`. The
browser retries dropped connections; when it gives up, the client reconnects with backoff
(1 s doubling to 30 s) and refetches active queries.

Before features hear about an event, its cache is patched: `project.created` and
`project.updated` update the project list and detail, `device.status` the device list,
`job.updated` the job, and `resync` refetches everything. Features subscribe for the rest:

```ts
import { useLiveEvent, useLiveReconnect } from "@/lib/live";

useLiveEvent("conversation.message.delta", (event) => append(event.payload.text));
useLiveReconnect(() => void refetchMessages());
```

## Conversations

`features/conversation` is the project page's Chat tab: the conversation list (a column
from 768px, a picker below), the open conversation (`?conversation=<id>`, else the latest),
and the composer.

- Messages are read page by page to the end and kept oldest first. Assistant text is
  markdown (GFM); raw HTML shows as text, unsafe link targets are dropped and images become
  links.
- Sending adds a pending message keyed by its `clientMessageId`; the stored message takes
  over the same element. A failed send keeps the message with Retry, which reuses the id.
- `store.ts` holds what the API does not: pending messages, text streamed by
  `conversation.message.delta` (replaced by `conversation.message.created`), the latest
  `job.activity` per job and the job answering each conversation. `job-status.ts` turns a
  job into the status line; `scroll.ts` follows new content only while the view is at the
  end.
- ⌘Enter or Ctrl+Enter sends. Messages sent from the keyboard appear without animation.

## Knowledge base

`features/kb` is the project's Knowledge tab (`/projects/:id/kb`), its entry pages
(`kb/$entryId`) and the create forms (`kb/new?kind=brainstorm|note|decision|reference`).

- The list filters by kind (a segmented control), one tag (chips from `kb.tags`) and a search
  box debounced at 200 ms; all three live in the address. A query switches from `kb.list`
  (paged with Load more) to `kb.search`, whose snippets mark matches with the `\u0002` and
  `\u0003` sentinels. `lib/snippet.tsx` turns them into `<mark>` elements; stored text is never
  rendered as HTML, and markdown previews use the chat renderer with raw HTML shown as text.
- `kb.entry.created`, `updated` and `deleted` events patch every loaded list, the tags, the
  searches and the open entry (`queries.ts`, mounted once by the project layout).
- Brainstorms and notes open in an editor whose unsaved changes are kept in localStorage
  (`draft.ts`) and restored on return. ⌘S or Ctrl+S saves. Saves send `expectedUpdatedAt`; a
  `409` shows a banner to reload the stored version or overwrite it.
- The Decisions filter is a timeline, newest first. Supersede opens the create form with
  `supersedes`, and the API marks the old decision superseded.
- References store a link (never fetched), why it was saved and an optional transcript, pasted
  or loaded from a `.txt`, `.srt`, `.vtt` or `.json` word-list file the user owns. Files are
  parsed in the browser into `[mm:ss] text` lines (`transcript.ts`, at most 200,000
  characters). The detail page has find-in-transcript and the analysis panes; the Analyze
  button queues `kb.analyze_reference`, and `analysis-status.ts` combines the stored status
  with `job.updated` for the status pill.

## Library

`features/library` is the Library page (`/library`, every project) and each project's Content
tab (`/projects/:id/content`), the same view scoped to one project.

- Rows are 38px: title, series, state pill, version, target date, length and last change.
  Column headers sort the loaded rows; empty values sort last. One title link is in the tab
  order: arrow keys, Home and End move between rows and Enter opens the item.
- Filters live in the address, validated by `LibrarySearchSchema` (`search.ts`): `states`
  (comma-separated pipeline states; none means everything but archived), `series`, `from` and
  `to` (target days, inclusive, in the browser's time zone), `q` (debounced 200 ms) and `sort`
  (`title`, `-updated` and so on). Invalid values are dropped, not fatal. They map onto
  `content.list` with `states` sent comma-separated. A channel filter joins them once posts can
  be scheduled.
- `content.item.created` and `content.item.updated` patch every loaded list
  (`upsertContentItem` in `queries.ts`): an item is replaced, dropped when it no longer matches,
  or added at the top. Searched lists refetch instead, since only the server knows what a search
  matches. `content.version.created` refetches the open item.
- The Board view groups the same rows into one column per state (every state but archived,
  or the filtered states). It is read-only: items move through production and review, never
  by dragging. The table or board choice is kept in localStorage (`loomcast.library.view`).
- Each row and card has quick actions: Produce through review (`content.actions` with
  `produce` through `review`), Open, and Archive after a confirmation. What is enabled comes
  from `allowedActions` in the contracts; listed items carry no artifacts, and these actions
  need none.
- New idea asks for a title, an optional pitch and series, and, in the library, the project.
- The command palette searches videos by title and pitch across projects
  (`features/palette/sources/content.ts`, 150 ms debounce, older requests aborted).

## Item page

`features/content-item` is one video's page (`/content/:itemId`): the header, the active job, four
tabs and a rail. The address holds the tab (`?tab=script|storyboard|voice|video`, else the furthest
artifact), an earlier version to show (`?version=`) and a version to compare scripts with
(`?compare=`).

- Every action comes from `allowedActions` in the contracts for the item's state, the user's role
  and the current version: Produce (through review), Approve, Request changes, Reject (after a
  confirmation), Archive (after a confirmation) and Restore. There are no single-key shortcuts.
  The title is renamed in place (Enter saves, Escape cancels).
- The active job shows in a banner with its latest `job.activity` (a progress bar when the job
  reports one) and Cancel; when it finishes the item is read again. The last production error
  shows until the next step succeeds.
- Script: segments with mono timestamps (from the voice, or `~` estimated from the word count),
  the hook highlighted, on-screen text, and the word count and length against the series'
  format target (`series.get` then `formats.get`, or `formats.versions` for the version the
  content was produced with). Edit mode is segment fields: ⌥↑ and ⌥↓ move a segment, ⌥Enter
  adds one, ⌥Backspace removes an empty one, ⌘S saves. Compare renders a word diff (`diff`) as
  `<ins>` and `<del>`.
- Storyboard: one row per frame with its card, tier and purpose (read from the card id), the
  segment it plays over, a timing bar and the slot text; a frame's slots are edited in place.
- Voice: every take (`content.assets?kind=voice`) with a player; "Use this take" sets
  `voiceAssetId`, Regenerate queues a new take.
- Video: a 9:16 `<video>` with its poster that never autoplays; `,` and `.` step one frame while
  it has focus, the rate buttons change the speed, and the details come from `assets.get`.
  Download asks for an `attachment` URL.
- Every save is `content.versions.edit` on top of the version being edited. A `409 conflict`
  (or a newer version arriving while editing) shows a banner to reload or save on top.
- Media plays from presigned URLs (`asset-url.ts`): they stay fresh until a minute before they
  expire and are replaced on a timer before then; a player keeps its position and only resumes if
  it was playing. A `409` (still processing) is asked for again every few seconds.
- The rail holds the review panel (Approve only when allowed; Request changes needs a comment,
  "Ask the producer to revise" is on by default and ⌘Enter sends), the version timeline (pick a
  version to show it, or compare its script) and the item's producer chat: the conversation
  thread bound to `content.conversation`.
- Other features add cards to the page by adding a file to `features/content-item/cards/items/`
  that exports `card: {id, placement: "main" | "rail", order, component}`.
- Mock mode: versions carry real scripts and storyboards (`src/mocks/artifacts.ts`), voice takes
  play a quiet generated tone, posters are generated SVGs and renders a short clip recorded from a
  canvas in the page. Single production steps (Regenerate, Render) and revisions run too.

## Series and formats

`features/series` is the project's Series tab (`/projects/:id/series`) and each series' page
(`series/$seriesId`); `features/formats` is the format rules editor (`series/$seriesId/format`).

- The list shows each series' format, status, cadence (with the next slot) and the next video
  coming up. Archived series fold away behind "Show archived". New series takes a name and one
  of the project's formats, or creates a format with the default rules and opens it.
- The series page lists its unpublished videos by target date beside cards from a registry:
  every file in `features/series/cards/items/` exports one `card: {id, order, Card}` and gets
  `{series, project, format, projectParam}`. Cadence is 10 and Format 20; a channels card fits
  at 30. Pause and Archive ask first (pausing archives ideas planned for upcoming slots);
  Resume doesn't. Switching the series to another format is in the Format card.
- The editor is a react-hook-form over the contracts' `FormatRulesSchema` (and
  `FormatNameSchema`), so it accepts and refuses exactly what the API does. Empty optional
  fields are left out rather than sent as `""` (`normalizeRules`); errors land on the field their
  path names, including `400 validation_failed` details from the API (`rules.lengthSec.max`).
  Topics, words to avoid and hashtags are chips: Enter or a comma adds one, pasting several lines
  adds one per line, and "Paste a list" takes a longer one. Hashtags are stored without `#`.
- Cadence: day toggles, local times (up to 12), a searchable list of the browser's IANA time
  zones (`Intl.supportedValuesOf`; offsets are never offered) and the lead time, with the next
  five slots from `generateSlots` in the series' zone and the viewer's. Publish mode explains
  approval and automatic publishing.
- Every save stores a new version on top of the one the edit started from (`baseVersionId`);
  a `409` offers to load the newer version or save over it. ⌘S or Ctrl+S saves. The version
  history shows each version's changes from the one before as a JSON diff of the rules.
- Styles come from a short static list (`formats/styles.ts`) mirroring the studio's style
  library, since the browser can't read it; recipes come from `skills.list`, with their
  descriptions as hints.

## Review queue

`features/review-queue` is `/review` (`?project=<id>` narrows it): videos in review from
`reviews.queue`, the nearest target first, undated ones last, then the longest waiting. Rows
show the poster (a presigned URL refreshed before it expires), project, series, version, length
and a deadline badge (red once the date passed, amber within a day, blue within three). `j` and
`k` (or the arrows, Home and End once a row has focus) move between rows and Enter opens one;
nothing animates as they move. `content.item.*` events add, re-sort and drop rows.

## Analytics

`features/analytics` is `/analytics` (`?range=7d|30d|90d|12m&project=<id>`), each series' page
(`/analytics/series/:seriesId?range=all|90d|12m`) and the item page's Performance card
(`features/content-item/cards/items/analytics.tsx`). They read `analytics.overview`,
`analytics.series` and `analytics.item`: live posts only, each counted by its latest capture.

- Overview: headline tiles (posts published, total views, median views per post, engagement
  rate), views over time per platform and the ten most-viewed posts, then links to every series.
  Ranges are whole UTC days ending today, so the query key holds through a day. The trend is
  the running total of the posts' views by the day (45 days or less), week (200 or less) or month
  each post went live, zero-filled, so sparse publishing still reads as a line.
- Series page: tiles (with average watch time) and two aligned per-post bar charts on their own
  axes, views and average watch time, by publish date. Never two scales on one chart.
- Performance card: one live post at a time (picked by platform), its latest metrics with a
  sparkline over its captures, when it was captured, when the next capture is due and a link to
  the post. Nothing renders for items that never went live; the card and the chart code load as
  their own chunk.
- Charts are hand-drawn SVG over `d3-scale` and `d3-shape`. Platform colours are fixed slots
  (`platforms.ts`, `viz.css`: the validated data-viz palette, light and dark steps of the same
  hues), so a platform keeps its colour whatever else is on screen. Text never wears a series
  colour; legends and short line keys carry identity.
- Every chart has a Chart / Table toggle; the table prints the same formatted values as the
  tooltips and the points' accessible names (`tooltips.ts`). Points are transparent buttons over
  the SVG sharing one tab stop: arrow keys, Home and End move, focus or hover shows the tooltip,
  Escape hides it. Nothing animates as the active point moves; a refetch keeps the previous
  render, dimmed, instead of a skeleton.
- "Not enough data yet" replaces a chart without enough to draw (no captures, fewer than two
  periods or posts); empty ranges get an empty state. `post.metrics.updated` and reconnects
  refetch every analytics query.
- Mock mode: `src/mocks/analytics.ts` gives the demo series a back catalogue of published videos
  with captures on the insights schedule; the newest one went live minutes ago and has none yet.
  It runs after the calendar's seed: live posts go to the channels linked to each series and are
  also published (not dry-run) posts in the calendar, and the calendar's own dry-run posts stay
  unmeasured.
  Tests add captures with `addMetricsCapture`, which publishes `post.metrics.updated`.

## Reference media

A reference's Media card (`features/kb/ReferenceMediaUpload.tsx`, logic in `media-upload.ts`)
uploads the video or audio the user saved (MP4, MOV, MP3, WAV or M4A, up to 1 GiB) under the
notice "Only upload media you own or have permission to use.":

1. SHA-256 in 8 MiB slices with `hash-wasm` (Web Crypto over the whole file where a CSP blocks
   WebAssembly);
2. `assets.createUpload` (kind `reference_media`); `upload: null` means the project already
   has the file;
3. an XHR PUT with the signed headers and upload progress (fetch reports none);
4. `assets.finalize`, PUTting again once on `409 upload_missing`;
5. `kb.update` with `mediaAssetId`, then `kb.analyze`.

One progress bar covers all steps; Cancel or leaving the page aborts. A reference with media
can be analyzed without a transcript.

## Calendar

`features/calendar` is the Calendar page (`/calendar`): every post on every channel, by week or
by month.

- The address holds the view (`view=month`; week by default), any day of the period (`date`,
  `YYYY-MM-DD`; today when left out), the channel and series filters (`channels`, `series`,
  comma-separated ids) and the clock (`zone=series`). `CalendarSearchSchema` (`search.ts`) drops
  invalid values. Filters go to `calendar.get` as comma-separated `channelIds` and `seriesIds`.
- Times follow the browser's time zone. The series time zone (the cadence `tz` of the filtered
  series' formats, or of every series when unfiltered) can be chosen when they share one.
  `time.ts` computes periods with date-fns on `TZDate` (`@date-fns/tz`), so weeks across a
  daylight saving change are 167 or 169 hours, and maps cells to instants with the contracts'
  `fromLocalDateTime`, the rule the API and the scheduler use.
- The week has seven columns from 06:00 to midnight in half-hour rows that grow with their
  chips; posts before 06:00 get a lane above the grid. A month shows six weeks, three entries a
  day and "+n more", which opens that week. Chips show the platform dot, the title, the time and
  the post state. Cadence slots no post holds are drawn dashed.
- `←` and `→` change the period and `t` returns to today, except while typing, in menus and
  dialogs, and while dragging.
- Posts in `RESCHEDULABLE_POST_STATUSES` drag with dnd-kit: the mouse or a pen
  (`PointerSensor`, after 4px), a press-and-hold on touch, or the keyboard (Space picks up, the
  arrows move by half an hour or a day, a day or a week in the month view, Space or Enter drops,
  Escape cancels). Enter opens the video when not dragging. A pointer drag lifts a copy (scale
  1.02 and a deeper shadow over 160 ms; under reduced motion only the shadow); a keyboard drag
  moves a marker from cell to cell without animation, and focus returns to the post after the
  drop. Moves into the past (or the next two minutes) are refused.
- A drop patches every loaded range at once (`movePost` in `model.ts`) and sends
  `scheduledPosts.reschedule` with `expectedUpdatedAt`. A failure puts the post back
  (`rollbackMove`, which keeps a newer copy from a live event) and shows a toast; a `409` also
  refetches the calendar.
- Clicking an open slot lists the series' approved videos without an open post on that channel
  (`content.list` with `states=approved,scheduled`); picking one sends `scheduledPosts.create`.
- `post.updated` patches every loaded range (moved, added or dropped by range and filter),
  `channel.updated` the channel list and `content.item.updated` the titles and states on chips.
- Post states use a local mapping (`post-status.tsx`) until `StatusPill` gets a `post` kind.
- dnd-kit and date-fns stay in the calendar's route chunk.

## Screens and conventions

- Pages use `Page` and `PageHeader`. Lists sit in a card (`rounded-lg bg-card shadow-card`)
  with a 44px header and 40px rows. Every data view has loading (skeleton), empty, error with
  retry, and long-content states; names truncate and slugs hide on phones.
- Breadcrumbs come from route `staticData.breadcrumb`: a string, or a function of the params
  for labels that need data (see `_app/projects/$projectId/route.tsx`). Builds split every
  route's component into its own chunk, but `staticData` loads with the app: import crumbs
  from small modules of their own (`ProjectCrumb.tsx`, `KbEntryCrumb.tsx`, `ContentCrumb.tsx`),
  never from the page module, or the whole page lands in the entry chunk.
- The sidebar is 240px and becomes a sheet below 768px, the `@loomcast/ui` mobile breakpoint.
  Its items come from a registry: every file in `src/app/nav/items/` exports one
  `item: {id, label, icon, order, section?, to?, exact?, badge?}`, so a feature adds itself to
  the sidebar by adding a file. `section` is `main` (default) or `footer`; an item without `to`
  shows disabled with a "Soon" badge. The Channels group (`src/app/nav/channels-section.tsx`)
  lists the planned platforms (Facebook, Instagram, Threads, X) as coming soon.
- The project page (`features/project`) is a header and tabs over the open tab's route. Tabs
  come from a registry: every file in `features/project/tabs/items/` exports one
  `tab: {id, label, icon, to, order}`, so a feature adds a tab by adding a file. The tab whose
  path is the longest prefix of the location is active. Overview (the project root) holds the
  description editor, stats, recent activity and archiving; Chat is the conversation panel.
  A link to the project root with `?conversation=` opens the Chat tab.
- Settings: `settings/devices` pairs studio agents with single-use codes and shows live
  online status; `settings/tokens` manages access tokens and shows each secret exactly once,
  never keeping it in the query cache. The tabs come from a registry: every file in
  `features/settings-nav/items/` exports one `item: {id, label, description, icon, to, order,
  keywords?, visible?}`; `visible(me)` hides a section, as Members is hidden from admins.
- Members (`settings/members`, owner only, like every `/api/users` route): the people who can
  sign in with role, last sign-in and status, an invite dialog, a new password link and
  disabling (with confirmation; the owner and yourself can't be disabled). Invitation and
  reset links are shown once with a copy button and their expiry, live only in the dialog's
  state, and never reach the query or mutation cache.
- Set-password (`/set-password#token=…`, public): the page reads the token from the fragment
  and replaces the history entry without it before painting, so it stays in neither the URL
  nor the history. It shows who the link is for, takes a new password (12 characters or more)
  twice, and sends the user to sign in. Unknown, used and expired links (404) and rate limits
  (429) each get their own message. Neither the token nor the password is put in the query
  client.
- Command palette (`features/palette`): ⌘K or Ctrl+K anywhere, or the topbar button. It opens
  and closes without animation. Groups come from `features/palette/sources/*`, each exporting
  `source: {id, heading, order, icon, useItems(context)}` and filtering its own rows: projects
  (from the cached list), the knowledge base (server search after a 150 ms pause, from two
  characters, aborting the previous request), actions (new project, new brainstorm in the open
  project, switch theme) and pages (including the visible settings sections). Picked pages are
  kept per user in localStorage and shown under Recent. The palette body (cmdk, the command
  menu and the sources) is its own chunk: `features/palette/load.ts` starts loading it on idle
  after the shell mounts and when the pointer or focus reaches the search button, while the
  shortcut and the open state stay in the main chunk. Asked to open before the chunk is there,
  the palette appears as soon as it arrives, with no spinner.
- Theme: light, dark or system from the user menu, stored by `@loomcast/ui/lib/theme` and
  applied before first paint by `/theme-init.js`. Theme changes never animate.
- Motion stays inside the `@loomcast/ui` components: press feedback, dialog, menu and sheet
  enter and exit, and the tabs indicator. Keyboard actions do not animate, and reduced motion
  keeps fades only.
