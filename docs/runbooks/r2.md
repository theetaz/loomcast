# Cloudflare R2 object storage

Production keeps files in three Cloudflare R2 buckets, reached through R2's S3-compatible API.
Locally, SeaweedFS plays the same role ([local-development.md](../local-development.md)).

| Bucket | Access | Holds | Lifecycle |
|---|---|---|---|
| `loomcast-media` | Private | Drafts, voice takes, renders, posters, frames and reference media | Kept; incomplete multipart uploads expire after 7 days (R2's default rule) |
| `loomcast-public` | Public read through a custom domain | Final renders, copied by the publisher at publish time under an unguessable key, for the platforms to fetch | Deleted after **14 days** |
| `loomcast-backups` | Private | Nightly database backups (`daily/`, `weekly/`) | Deleted after **90 days** |

Bytes never pass through the api: clients upload with presigned `PUT` URLs straight to the R2
endpoint, and read private files with presigned `GET` URLs. Only the api holds R2 credentials.

Account IDs, access keys and secrets never go into this repository, a chat, an issue or shell
history. Commands use placeholders such as `<account-id>`.

## Owner decisions (C4)

> **Owner checkpoint C4.** The owner creates the buckets, the custom domain, the CORS and
> lifecycle rules and the two API tokens in the Cloudflare dashboard, and puts the keys into the
> server's env files (or hands them over by the agreed secure route, never in plain text). This
> happens before go-live (G1).

| Decision | Recommendation |
|---|---|
| Public media hostname | A **first-level** name such as `loomcast-media.prabhavalabs.com`. Cloudflare's free Universal certificate covers only the zone apex and first-level names; a second-level name such as `media.loomcast.prabhavalabs.com` needs an advanced certificate (Advanced Certificate Manager) or a custom certificate. Check SSL/TLS → Edge Certificates covers the chosen name before connecting it. |
| Bucket location | Automatic, or a location hint near the server. Keep the default jurisdiction unless data must stay in the EU; an EU jurisdiction changes the endpoint (`https://<account-id>.eu.r2.cloudflarestorage.com`) and the token scope. |
| Bucket lock on `loomcast-backups` | Optional: a retention lock (for example 30 days) stops anyone holding a key from deleting recent backups. |

## 1. Enable R2 and note the endpoint

R2 object storage → Overview. Enable R2 for the account if it is not yet enabled, and note the
**Account ID** shown there. The S3 endpoint is:

```text
https://<account-id>.r2.cloudflarestorage.com
```

## 2. Create the buckets

R2 object storage → Create bucket, three times:

| Name | Location | Storage class |
|---|---|---|
| `loomcast-media` | as decided | Standard |
| `loomcast-public` | as decided | Standard |
| `loomcast-backups` | as decided | Standard |

For each bucket, open Settings → **Public Development URL** and make sure it is **disabled**
(`r2.dev`). Disabling it does not affect custom domains.

## 3. Custom domain for `loomcast-public`

`loomcast-public` → Settings → Custom Domains → Add → enter the chosen hostname → Continue →
review the DNS record Cloudflare adds → Connect Domain. Wait until the status is **Active**
(a few minutes; use **Retry connection** from the bucket's menu if it stalls).

`loomcast-media` and `loomcast-backups` get **no** custom domain.

## 4. CORS on `loomcast-media`

Browsers upload reference media with presigned `PUT` requests and preview files with presigned
`GET` requests, so `loomcast-media` must allow the app's origin. The rule is in
[`infra/r2/cors.media.json`](../../infra/r2/cors.media.json):

- `AllowedOrigins`: `https://loomcast.prabhavalabs.com` only.
- `AllowedMethods`: `GET`, `HEAD`, `PUT`.
- `AllowedHeaders`: the content type and the checksum headers a presigned upload carries.
- `ExposeHeaders`: `ETag` (the upload's hash) and the length and type.
- `MaxAgeSeconds`: 3600, so browsers cache the preflight for an hour.

`loomcast-media` → Settings → CORS Policy → Add CORS policy → **JSON** tab. The dashboard takes the
bare list of rules, so paste the array that follows `"CORSRules":` in the file (from `[` to the
matching `]`), then save.

`loomcast-public` and `loomcast-backups` need no CORS: the platforms fetch public media from their
servers, and backups are never read from a browser. If the app's origin ever changes, update the
file and the policy together.

## 5. Lifecycle rules

`loomcast-public` → Settings → Object lifecycle rules → Add rule:

- Name `expire-after-14-days`, applies to all objects (no prefix), delete objects **14 days**
  after upload. Save.

`loomcast-backups` → Settings → Object lifecycle rules → Add rule:

- Name `expire-after-90-days`, applies to all objects, delete objects **90 days** after upload.
  Save.

Leave R2's default rule (abort incomplete multipart uploads after 7 days) on all three buckets.
`loomcast-media` gets no expiry rule: the app deletes what it no longer needs.

The 14 days are plenty: the publisher copies a render to `loomcast-public` only when the post is
published, and the platforms fetch it within minutes. The 90 days cover the backup rotation, which
keeps 14 daily and 8 weekly copies on the server as well.

## 6. API tokens

R2 object storage → Manage API tokens → **Create Account API token** (account tokens keep working
if a user leaves the account). Create two:

| Token name | Permission | Buckets | Client IP filter | Used by |
|---|---|---|---|---|
| `loomcast-app` | Object Read & Write | `loomcast-media`, `loomcast-public` | **None** | The api: `S3_ACCESS_KEY`, `S3_SECRET_KEY` in `/opt/loomcast/env/api.env` |
| `loomcast-backup` | Object Read & Write | `loomcast-backups` | `<vps-ipv4>` | The backup service: its env file, see the backup runbook |

- Do not IP-filter `loomcast-app`. Presigned URLs are signed with its key and used by browsers
  and the studio agent from other addresses; a filter would reject them.
- Object permissions cannot change bucket settings (CORS, lifecycle, custom domains), which stay
  with the owner's dashboard login.
- Each token shows its **Access Key ID** and **Secret Access Key** once. Copy them straight into
  the env files on the server (mode 0600; open them in an editor rather than echoing values on the
  command line), then close the page.

## 7. Api settings

In `/opt/loomcast/env/api.env` (the lines are commented out in `api.env.example` until object
storage ships; uncomment them then):

| Variable | Value |
|---|---|
| `S3_ENDPOINT` | `https://<account-id>.r2.cloudflarestorage.com` |
| `S3_REGION` | `auto` |
| `S3_FORCE_PATH_STYLE` | leave empty (R2 accepts both styles) |
| `S3_BUCKET` | `loomcast-media` |
| `S3_PUBLIC_BUCKET` | `loomcast-public` |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | from `loomcast-app` |
| `PUBLIC_BASE_URL` | `https://<media-host>`, the custom domain from step 3, no trailing slash |

Restart the api afterwards (`docker compose -p loomcast … up -d`, see
`infra/compose/README.md`).

## 8. Verify

Run these on the server (Docker is there) with the `loomcast-app` keys, read without echoing them.
The AWS CLI image is the one the project already uses; the two checksum settings keep the CLI's
newer default integrity headers out of the requests.

```bash
read -rs -p 'Access key ID: ' AWS_ACCESS_KEY_ID; echo
read -rs -p 'Secret access key: ' AWS_SECRET_ACCESS_KEY; echo
export AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY
R2=https://<account-id>.r2.cloudflarestorage.com
s3() {
  docker run --rm -e AWS_ACCESS_KEY_ID -e AWS_SECRET_ACCESS_KEY -e AWS_DEFAULT_REGION=auto \
    -e AWS_REQUEST_CHECKSUM_CALCULATION=when_required \
    -e AWS_RESPONSE_CHECKSUM_VALIDATION=when_required \
    -v "$PWD:/work" -w /work amazon/aws-cli:2.31.0 --endpoint-url "$R2" "$@"
}

printf 'probe\n' >probe.txt
s3 s3 cp probe.txt s3://loomcast-public/probe/probe.txt
curl -sS https://<media-host>/probe/probe.txt                     # prints probe
s3 s3 cp probe.txt s3://loomcast-media/probe/probe.txt
curl -sS -o /dev/null -w '%{http_code}\n' "$R2/loomcast-media/probe/probe.txt"   # 400 or 403: private
s3 s3 ls s3://loomcast-backups/                                   # AccessDenied: wrong token, as intended

# CORS preflight for a browser upload
curl -sS -o /dev/null -D - -X OPTIONS "$R2/loomcast-media/probe/probe.txt" \
  -H 'Origin: https://loomcast.prabhavalabs.com' \
  -H 'Access-Control-Request-Method: PUT' \
  -H 'Access-Control-Request-Headers: content-type,x-amz-checksum-sha256' |
  grep -i '^access-control-allow'

s3 s3 rm s3://loomcast-public/probe/probe.txt
s3 s3 rm s3://loomcast-media/probe/probe.txt
rm probe.txt
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY
```

Repeat the copy, list and delete with the `loomcast-backup` keys against `loomcast-backups` (and
confirm they are refused on the other two buckets).

## Rotating or revoking a key

1. Create a new token with the same permissions.
2. Put its keys into the env file and restart the service that uses it.
3. Check the service works (the api's `/readyz`, or a manual backup run).
4. Delete the old token in R2 object storage → Manage API tokens.

If a key may have leaked, delete its token first and accept the short outage.

## Before browser uploads go live

The app's Content Security Policy currently allows connections and media only from its own
origin. Browser uploads to the R2 endpoint and previews from it need `connect-src` and `media-src`
(and `img-src` for posters) to include `https://<account-id>.r2.cloudflarestorage.com`; showing
published renders from the public bucket needs the media hostname. That is a change to the api's
headers, made together with the storage feature, not part of this runbook.
